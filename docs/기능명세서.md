## 1. 현행 분석

| 항목 | ESC_SPEAKING (영작 · 단어 나열) | ESC_WORD (단어 공부) |
|---|---|---|
| 구조 | `index.html` + `script.js` + `style.css` + `data.json` | `index.html` 한 파일(인라인 CSS/JS) + `data.json` |
| 데이터 | 패키지 118개 × 문장 10개. `{title, type, date, questions:[{ko, en, distractors}]}` | 세트 39개 × 단어 14~15개. `{title, date, questions:[{meaning, answers[], sentence}]}` |
| 핵심 동작 | `en`을 공백으로 나눈 단어 + 오답 단어를 섞어 버튼으로 표시 → 탭으로 순서대로 배치 → 문장 비교 | 학습 모드(카드 + TTS 발음) / 테스트 모드(뜻·예문 보고 입력, 입력 즉시 정답 판정, 60% 이상 통과) |
| 목록 | 유형 필터 + 검색 + 가상 스크롤 | 검색 + 20개씩 더보기, **미래 날짜 숙제 숨김** |
| 완료 처리 | 완료 화면 캡처 → 톡방 인증 | 결과 화면(정답 수, 완료 시각) |
| 저장 | 없음 | 없음 |

이관 시 반드시 유지할 동작:

- SPEAKING: 단어 버튼의 구두점 포함 표기(`tea.`), 정답 비교는 `selectedWords.join(" ") === en` 그대로, 오답 시 정답 모달 → 같은 문제 재시도, 완료 화면의 **인증 일시**와 캡처 안내 문구.
- WORD: 미래 날짜 숙제 숨김, `answers` 배열 중 하나만 맞아도 정답, 테스트 결과 60% 기준, 학습 모드 TTS(카카오 인앱 브라우저 미지원 안내 포함).

발견된 문제(통합 시 같이 해결):

- **숙제에 안정적인 ID가 없음.** SPEAKING은 `hw-package-${배열 인덱스}`로 ID를 만들고, WORD는 배열 인덱스를 그대로 씀. 데이터 중간에 숙제를 추가·삭제하면 ID가 밀려 **기록이 다른 숙제에 붙는다.** → [2.4](#24-콘텐츠-id-규칙) 참고.
- `type`이 없는 패키지 1개 존재(현재 '미분류'로 표시). `구동사` 유형은 필터 목록에 없음 → 필터는 데이터에서 자동 생성.

## 2. 통합 구조와 화면 목록

### 2.1 기술 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 프론트엔드 | 지금처럼 **정적 HTML/CSS/바닐라 JS**, 해시 라우터(`#/order`, `#/blank` …) | 기존 코드 재사용이 쉽고 GitHub Pages에 그대로 배포 가능. 빌드 도구 불필요 |
| 호스팅 | GitHub Pages (`ESC_English` 저장소) | 기존 두 서비스와 동일 |
| 인증 + DB | **Supabase** (Auth + Postgres + Row Level Security) | 서버 없이 정적 사이트에서 OAuth·DB 사용 가능. 카카오/구글 Provider 기본 제공. 무료 플랜으로 충분 |
| 콘텐츠 | 기존 `data.json` 두 개 + 빈칸용 `blank-data.json`(구글 시트에서 생성) | 콘텐츠는 정적 파일로 두고, DB에는 **사용자 기록만** 저장 |

대안: Firebase Auth + Firestore도 가능하지만 카카오 로그인이 기본 Provider가 아니라 Cloud Functions(커스텀 토큰)가 필요함 → Supabase 권장.

### 2.2 라우트 / 화면 목록

| 라우트 | 화면 | 비고 |
|---|---|---|
| `#/` | 홈 — 모듈 카드 3개, (로그인 시) 오늘 요약, (비로그인 시) 로그인 유도 배너 | |

| `#/order/done` | 영작 완료 — 걸린 시간, 재도전 횟수, 인증 일시, **탭/스피킹 비율** | |
| `#/word` | 단어 세트 목록 | |

| `#/blank` | 빈칸 홈 — 진도, 학습 시작, 복습, 심연 | [5장](#5-기능-2--빈칸-표현-학습) |
| `#/blank/play/new` · `#/blank/play/review` | 빈칸 풀이 | |

| `#/me` | 내 기록 (비로그인 시 로그인 유도) | [7장](#7-내-기록-화면) |
| (오버레이) | 로그인 바텀시트 | 어느 화면에서든 상단 `로그인` 버튼으로 열림 |

공통 규칙:

- 상단 바: 홈은 `🍀 ESC` 로고, 그 외 화면은 `← 제목`. 오른쪽은 항상 계정 버튼(비로그인 `로그인`, 로그인 시 아바타+이름 → `#/me`).
- 풀이 화면에서 뒤로가기 시 진행 상황은 버림(현행과 동일). 단, 빈칸 학습은 문항 단위로 즉시 저장되므로 버려지지 않음.
- 기존 두 사이트 주소는 새 사이트로 리다이렉트(`<meta http-equiv="refresh">` + 안내 문구)하여 톡방에 공유된 링크가 깨지지 않게 함.

### 2.3 디자인 원칙 (프로토타입 기준)

- ESC_SPEAKING의 따뜻한 회색 톤을 기본으로, 모듈별 포인트 색만 구분: 영작 초록, 단어 파랑, 빈칸 주황, 심연 보라, 음성 빨강.
- 모바일 우선(최대 폭 720px), 하단 고정 액션 바(엄지 영역), 다크 모드 지원(`prefers-color-scheme`).
- 색상은 `:root` CSS 변수로만 사용 → 테마 변경은 변수만 수정.

### 2.4 콘텐츠 ID 규칙

기록은 콘텐츠 ID에 붙으므로 **ID는 한 번 정하면 바뀌지 않아야 함.**

- 영작/단어: `data.json`의 각 패키지에 `id` 필드를 추가. 형식 `ord-YYYYMMDD-slug`, `wrd-YYYYMMDD-slug` (예: `ord-20260601-dont-tell-me`). 이관 스크립트로 기존 항목에 1회 부여하고, 이후 추가하는 항목은 직접 작성. 앱은 `id`가 없는 항목을 목록에서 제외하고 콘솔에 경고.
- 영작 문장 단위 기록이 필요하면 `${packageId}#${문장 순번}`.
- 빈칸: 구글 시트에 `ID` 열 추가 ([5.2](#52-데이터-소스와-변환)).

## 3. 기능 0 — OAuth 로그인과 학습 기록

### 3.1 요구사항

| # | 요구사항 |
|---|---|
| A-1 | 로그인하지 않아도 **모든 학습 기능을 그대로 이용**할 수 있다. 로그인을 강제하는 화면은 없다. |
| A-2 | 로그인하면 자신의 기록(어떤 숙제를 했는지/안 했는지, 점수, 빈칸 진도·복습 목록)을 볼 수 있고 기기 간에 이어진다. |
| A-3 | 한 번 로그인하면 브라우저를 닫았다 열어도 자동으로 로그인되어 있다(“로그인 상태 유지”). |
| A-4 | 비로그인 상태로 쌓은 기록은 로그인하는 순간 계정으로 합쳐진다. |

### 3.2 로그인 수단

| Provider | 우선순위 | 비고 |
|---|---|---|
| **카카오** | 1순위(맨 위, 노란 버튼) | 사용자 대부분이 카카오톡 링크로 들어옴. 카카오톡 인앱 브라우저에서도 정상 동작 |
| **Google** | 2순위 | 카카오톡/인스타그램 등 **인앱 브라우저(WebView)에서는 Google이 로그인을 차단**함(`403 disallowed_useragent`) |

인앱 브라우저 처리:

1. `navigator.userAgent`에 `KAKAOTALK`이 있으면 Google 버튼을 비활성화하고 안내 문구 표시: “카카오톡 안에서는 Google 로그인이 막혀 있어요. ⋯ → 다른 브라우저로 열기를 누르거나 카카오 로그인을 이용해 주세요.” (프로토타입: `?inapp=1`로 확인 가능)
2. (선택) “외부 브라우저로 열기” 버튼 제공: 카카오톡 전용 스킴 `kakaotalk://web/openExternal?url=<인코딩된 현재 URL>`. 실제 기기(iOS/Android)에서 동작 검증 후 적용.
3. 인스타그램(`Instagram`), 라인(`Line/`), 네이버 앱(`NAVER(inapp`) 등도 같은 방식으로 감지 목록에 추가.

### 3.3 로그인 흐름

```
[로그인 버튼] → 바텀시트 → [카카오로 계속하기]
  → supabase.auth.signInWithOAuth({ provider: 'kakao', options: { redirectTo: 현재 URL } })
  → 카카오 동의 화면 → Supabase 콜백 → 원래 화면으로 복귀(PKCE 코드 교환)
  → onAuthStateChange('SIGNED_IN') → 게스트 기록 병합(3.6) → 서버 기록 로드 → 화면 갱신 + 토스트
```

- `redirectTo`에는 해시를 포함한 **현재 위치**를 넘겨, 로그인 후 보던 화면으로 돌아간다. (Supabase 대시보드 Redirect URL 허용 목록에 `https://<계정>.github.io/ESC_English/**` 등록)
- 받는 프로필 정보: 고유 ID, 닉네임, 프로필 이미지(선택). **이메일·전화번호는 요청하지 않음**(카카오 비즈 앱 심사 불필요, 개인정보 최소화).
- 표시 이름: 카카오 닉네임 / Google 이름. `#/me`에서 변경 가능(선택 기능).

### 3.4 자동 로그인 — 웹에서도 되나요?

**됩니다.** 앱처럼 “한 번 로그인하면 계속 로그인된 상태”를 웹에서도 구현할 수 있습니다.

- 원리: 로그인 시 짧은 수명의 **access token**(기본 1시간)과 긴 수명의 **refresh token**을 받아 브라우저 `localStorage`에 저장합니다. 다음 방문 때 Supabase JS가 저장된 refresh token으로 새 access token을 자동 발급받으므로 사용자는 다시 로그인할 필요가 없습니다. (`createClient(url, key, { auth: { persistSession: true, autoRefreshToken: true } })`)
- “로그인 상태 유지” 체크 해제 시: 토큰 저장소를 `sessionStorage`로 바꿔 탭/브라우저를 닫으면 로그아웃되게 함(`auth.storage` 커스텀 어댑터). 체크 여부는 `localStorage['esc.keepLogin']`에 기억.
- 세션 만료 정책: Supabase 기본값(refresh token 미사용 시 만료 없음)을 쓰되, 필요하면 대시보드에서 “비활성 세션 타임아웃”을 90일로 설정.

자동 로그인이 풀리는 경우(사용자 안내용 FAQ에 포함):

| 상황 | 이유 | 대응 |
|---|---|---|
| iPhone Safari에서 **7일 넘게 방문하지 않음** | Safari의 추적 방지(ITP)가 스크립트로 저장한 데이터를 7일 뒤 삭제할 수 있음 | **홈 화면에 추가**(웹앱으로 설치)하면 이 제한이 적용되지 않음 → 홈에 “홈 화면에 추가” 안내 카드 노출(iOS Safari에서만) |
| 카카오톡 인앱 브라우저 ↔ Safari/Chrome을 오갈 때 | 인앱 브라우저와 일반 브라우저는 저장소가 따로 | 각 브라우저에서 한 번씩 로그인. 기록은 계정에 있으므로 어디서든 같음 |
| 시크릿 모드, 사이트 데이터 삭제 | 저장소가 비워짐 | 다시 로그인 |
| 사용자가 다른 기기에서 “모든 기기 로그아웃” | refresh token 폐기 | 다시 로그인 |

### 3.5 저장하는 기록

| 모듈 | 저장 시점 | 저장 내용 |
|---|---|---|
| 영작 | 완료 화면 진입 시 | 패키지 ID, 완료 시각, 걸린 시간, 오답 재도전 횟수, 탭 단어 수, 음성 단어 수 |
| 단어 | 테스트 결과 화면 진입 시 | 세트 ID, 점수/문항 수, 통과 여부, 응시 시각 (학습 모드는 “학습함” 플래그만) |
| 빈칸 | **문항 하나 답할 때마다** | 진도(cursor), 문항별 상태(복습함/심연, 복습 정답 횟수, 마지막 출제 시각), 정답/오답 로그 |

- “했다/안 했다”의 정의: 영작 = 마지막 문장까지 완료, 단어 = 테스트 1회 이상 응시(통과 여부는 별도 표시), 빈칸 = 진도로 표시.
- 같은 숙제를 여러 번 하면 시도마다 행을 남기고, 화면에는 최근/최고 기록을 표시.

### 3.6 비로그인 기록과 병합

- 비로그인 상태에서도 기록 구조는 같고, 저장소만 `localStorage['esc.guest.v1']`(JSON)로 다름. 그래서 비로그인 사용자도 **같은 기기에서는** 빈칸 진도·복습이 이어짐(홈 배너: “지금은 이 기기에만 진도가 저장돼요”).
- 로그인 직후 1회 병합:
  - 영작/단어 시도 기록: 합집합(중복 시도는 `client_attempt_id`로 제거).
  - 빈칸 진도 `cursor`: 둘 중 큰 값.
  - 빈칸 문항 상태: 같은 문항이 양쪽에 있으면 **더 약한 상태를 채택**(복습함 > 심연, 복습 정답 횟수는 작은 값). 잊은 걸 외운 걸로 처리하는 것보다 안전.
  - 병합 성공 후 게스트 저장소 비움. 토스트: “이 기기의 기록을 계정에 합쳤어요.”
- 로그아웃 시: 서버 기록은 그대로, 이 기기는 다시 빈 게스트 상태로 시작.

### 3.7 계정 관리

- `#/me` 하단: 로그아웃, (설정 메뉴) 계정 삭제 — 확인 모달 후 Supabase Edge Function으로 사용자와 모든 기록 삭제.
- 개인정보 처리방침 페이지(`#/privacy`) 추가: 수집 항목(Provider ID, 닉네임, 학습 기록), 보관 기간(탈퇴 시 즉시 삭제), 음성 데이터 처리(4.7).

### 3.8 수용 기준

## 4. 기능 1 — 영작(단어 나열) 음성 입력

### 4.1 요구사항

| # | 요구사항 |
|---|---|
| V-1 | 풀이 화면에 🎤 버튼을 둔다(하단 액션 바, 확인 버튼 왼쪽). |
| V-2 | 🎤를 켜고 영어로 말하면, 인식된 단어가 아직 남아 있는 단어 버튼과 일치할 때 **그 버튼을 탭한 것과 똑같이** 답 영역 끝에 추가된다. |
| V-3 | 탭과 음성은 섞어서 쓸 수 있다. 음성으로 들어간 단어도 탭하면 다시 빠진다. |
| V-4 | 완료 화면에 **탭으로 넣은 단어와 스피킹으로 넣은 단어의 비율**을 표시한다. |

### 4.2 화면 (프로토타입 `#/order/play/:id`)

- 🎤 버튼 상태: 꺼짐(테두리) / 듣는 중(빨간 배경 + 바깥 링) / 미지원(비활성, 탭 시 토스트로 이유 안내).
- 듣는 중일 때 단어 버튼 아래 **인식 패널** 표시: 빨간 점(맥박 애니메이션) + 최근 인식 단어 6개. 단어 버튼과 맞은 단어는 초록, 맞는 버튼이 없는 단어는 회색 취소선.
- 음성으로 들어간 단어 버튼: 빨간 테두리 + 오른쪽 위 🎤 배지, 들어가는 순간 0.6초 빨간 깜빡임.
- 답 영역이 비었을 때 안내 문구: “단어를 탭하거나 🎤 버튼을 누르고 말해 보세요”.

### 4.3 음성 인식 엔진

- 브라우저 내장 **Web Speech API** `SpeechRecognition`(`window.SpeechRecognition || window.webkitSpeechRecognition`). 별도 비용·서버 없음.
- 설정: `lang = 'en-US'`, `interimResults = true`, `continuous = true`, `maxAlternatives = 3`.
- 지원 현황(2026년 기준, 출시 전 실제 기기 확인 필요):

| 환경 | 지원 | 비고 |
|---|---|---|
| Android Chrome, PC Chrome/Edge | ✅ | 음성이 Google 서버로 전송되어 인식됨 |
| iOS Safari (14.5+) | ✅ | `continuous`가 무시되고 몇 초 침묵하면 끝나는 경우가 있어 자동 재시작 필요 |
| iOS의 다른 브라우저(Chrome 등) | ⚠️ | WebKit 기반이라 Safari와 같지만 마이크 권한 동작이 다를 수 있음 |
| 카카오톡 인앱 브라우저 | ⚠️ 기기마다 다름 | Android WebView는 대부분 미지원 → 미지원 처리 |
| Firefox | ❌ | 미지원 처리 |

- 미지원 감지: 생성자가 없거나, `start()` 시 `not-allowed`/`service-not-allowed`/`audio-capture` 오류 → 🎤 비활성 + “이 브라우저에서는 음성 입력을 쓸 수 없어요. Chrome이나 Safari로 열어 주세요.”

### 4.4 동작 흐름

1. 🎤 탭 → (처음이면) 브라우저 마이크 권한 요청 → `start()` → 듣는 중 상태.
2. `onresult`에서 **확정 결과(`isFinal`)만** 단어 배치에 반영. 중간 결과(interim)는 인식 패널에 회색으로 미리보기만 한다. (중간 결과를 바로 반영하면 같은 단어가 두 번 들어가거나, 인식이 고쳐질 때 이미 들어간 단어를 되돌려야 하는 문제가 생김)
   - 반응 속도 개선 옵션: 중간 결과 중 **앞쪽 단어가 2회 연속 같은 값으로 유지되면** 확정으로 간주해 먼저 반영하고, 이미 반영한 단어 수를 기억해 확정 결과에서 중복 반영하지 않는다. 1차 구현은 확정 결과만, 체감이 느리면 이 옵션을 켠다.
3. 확정 결과 문자열을 토큰으로 나눠 [4.5 매칭](#45-단어-매칭-규칙)을 순서대로 적용.
4. 종료 조건: 🎤 다시 탭 / 확인 버튼 / 다음 문제로 넘어감 / 화면 이탈 / 정답 단어 수만큼 배치됨 / 10초간 인식 없음. 그 외에 `onend`가 오면(iOS 침묵 종료 등) 듣는 중 상태라면 자동으로 `start()` 재호출(연속 3회 실패 시 끔).
5. 문제가 바뀌면 인식 패널을 비우고, 🎤 상태는 꺼짐으로 초기화(자동으로 계속 듣지 않음 — 의도치 않은 녹음 방지).

### 4.5 단어 매칭 규칙

**정규화** (단어 버튼 텍스트와 인식된 토큰 모두에 적용):

1. 소문자로 변환.
2. 곡선 따옴표 `’ ‘ ʼ` → `'`.
3. 앞뒤 구두점 제거: `. , ! ? ; : " ( )` (버튼 `tea.` → `tea`, `Don't`의 `'`처럼 단어 안의 아포스트로피는 유지).
4. 하이픈 단어는 그대로 비교하고, 안 맞으면 하이픈을 공백으로 바꿔 두 토큰으로 다시 시도(`well-known` ↔ `well known`).

**매칭 순서** (인식된 토큰 하나마다):

1. 남아 있는 단어 버튼 중 정규화 값이 **정확히 같은** 버튼을 찾는다. 같은 단어 버튼이 여러 개면 화면상 첫 번째 것.
2. 없으면 **동치 사전**으로 바꿔 다시 찾는다:
   - 숫자 ↔ 영단어: `2`↔`two`, `10`↔`ten`, `1st`↔`first` …(0~100, 서수 1~31)
   - 축약형 ↔ 풀어 쓴 형태: 인식기가 `do not`으로 돌려준 경우 버튼 `don't`와 매칭(두 토큰을 묶어서 비교). 반대로 `I'm` ↔ `I am`도 동일. 사전: `n't`, `'m`, `'re`, `'s`, `'ll`, `'ve`, `'d`.
   - 자주 틀리는 동음어: `to/too/two`, `there/their/they're`, `your/you're`, `its/it's`, `know/no`, `right/write`, `here/hear`, `for/four`, `by/buy/bye`, `wear/where`, `weather/whether` — **남은 버튼 중 하나만** 해당될 때만 매칭(둘 이상이면 모호하므로 매칭하지 않음).
3. 그래도 없으면 매칭하지 않고 인식 패널에 취소선으로 표시. (오답 단어 `lately`를 `late`로 바꿔 넣는 식의 **유사어 추정은 하지 않음** — 이 게임의 목적이 형태 구분이므로)
4. `maxAlternatives`가 3이므로, 1순위 문장에서 매칭이 하나도 안 되면 2·3순위 문장으로 다시 시도.

**대소문자**: `This`와 `this`가 둘 다 버튼에 있는 경우는 없도록 콘텐츠가 만들어져 있음(문장 첫 단어만 대문자). 혹시 있으면 남은 정답 순서상 다음에 올 버튼을 우선.

**순서**: 말한 순서대로 답 영역 끝에 붙인다. 정답 여부는 판단하지 않는다(틀린 순서로 말하면 틀린 순서로 들어감 — 탭과 동일).

### 4.6 탭/스피킹 비율 계산

- 단어 하나하나에 `source: 'tap' | 'voice'`를 기록한다. 음성으로 넣었다가 빼고 다시 탭으로 넣으면 `tap`(마지막으로 넣은 방법 기준).
- **집계 대상은 정답 처리된 문장의 최종 배치 단어만.** 오답 제출이나 넣었다 뺀 단어는 비율에 포함하지 않는다(“최종적으로 문장을 어떻게 완성했는가”를 보여주기 위함).
- 패키지 단위 합계: `tapWords`, `voiceWords`. 비율 = `voiceWords / (tapWords + voiceWords)`, 정수 %로 반올림하고 탭% = 100 − 스피킹%.
- 완료 화면 표시(프로토타입 `#/order/done`):
  - “입력 방식 🎤 스피킹 37%” + 2색 막대(탭 진회색 / 스피킹 빨강) + 범례 “탭 63% (55단어) · 스피킹 37% (32단어)”.
  - 음성을 한 번도 안 썼으면 “탭 100%”로 표시하고, 아래에 작게 “🎤 버튼으로 말해서 입력해 보세요” 팁.
- 기록 저장 시 `tap_words`, `voice_words`를 함께 저장해 `#/me` 숙제 목록에 “🎤 32%”로 표시.
- (선택) 보조 지표로 “음성 인식 성공률” = 매칭된 토큰 / 인식된 전체 토큰. 완료 화면에는 표시하지 않고 기록에만 저장(콘텐츠/인식 품질 점검용).

### 4.7 개인정보

- 음성은 저장하지 않는다. 다만 Chrome은 인식을 위해 음성을 Google 서버로 보내므로, 🎤를 **처음 누를 때 1회** 안내: “말한 내용은 영어 인식을 위해 브라우저(구글/애플) 음성 인식 서비스로 전송되며, ESC는 음성을 저장하지 않아요.” [확인] 후 시작. 확인 여부는 `localStorage`에 기억.

### 4.8 수용 기준

- [ ] “This song is not my cup of tea.” 문제에서 “this song is not”이라고 말하면 4개 버튼이 순서대로 답 영역으로 이동하고 🎤 배지가 붙는다.
- [ ] 버튼이 `tea.`일 때 “tea”라고 말해도 매칭된다.
- [ ] 오답 단어 `lately`만 남아 있을 때 “late”라고 말하면 아무것도 들어가지 않는다.
- [ ] 탭 7단어 + 음성 3단어로 문장을 완성하면 그 문장 기여분은 탭 70% / 스피킹 30%.
- [ ] 미지원 브라우저에서 🎤가 비활성이고 이유가 안내된다. 탭 풀이는 영향 없음.
- [ ] 다음 문제로 넘어가면 듣기가 꺼진다.

### 5.2 데이터 소스와 변환

원본: 구글 시트 `1FtjsJBMbKby1pPa-_rjUQ9uBuoEIvOIem49bWMpR4dc`

| 탭 | 행 수(헤더 제외) | 열 |
|---|---|---|

| `문장구조` | 약 3,260 | 시즌, 화, 패턴, 구조 설명, 예문 (직접 작성), 난이도 |

**1차 범위는 `표현` 탭.** `문장구조` 탭은 2차(5.10)로 둔다.

#### 문제: 예문 속 표현은 원형 그대로가 아니다

시트를 확인한 결과, `표현` 열의 문자열이 예문에 그대로 들어 있지 않은 경우가 많다.

| 유형 | 표현 | 예문 | 빈칸이 되어야 할 부분 |
|---|---|---|---|
| 그대로 | freak out | Don't **freak out**, it's just a small spider. | `freak out` |
| 동사 활용 | go through | She **went through** a tough year at work. | `went through` |
| 진행형 | go out with | I'm **going out with** Jake this Friday. | `going out with` |
| be 동사 활용 | be up to | What **are** you **up to** tonight? | `are` … `up to` (빈칸 2개) |
| 목적어가 끼어듦(분리형) | put together | We **put** the bookshelf **together** in an hour. | `put` … `together` |
| 대명사 자리 | stand someone up | She **stood** me **up** at the restaurant. | `stood` … `up` |
| 소유격 자리 | make a fool of oneself | I **made a fool of** myself … | `made a fool of` |
| 문법 표기 포함 | start + -ing | It **started** raining … | `started` |
| 괄호 선택 | let go (of) | It's time to **let go of** the past. | `let go of` |
| 문두 대문자 | steer clear of | **Steer clear of** that road … | `Steer clear of` |

그래서 **빈칸 위치를 문장마다 명시하는 열**을 시트에 추가한다.

#### 시트에 추가할 열

| 열 | 예 | 설명 |
|---|---|---|
| `ID` | `EX-S01E01-07` | 문항 고유 ID. **한 번 정하면 수정 금지**(기록이 이 ID에 붙음). 형식 `EX-{시즌}{화}-{화 안 순번 2자리}` |
| `빈칸 예문` | `We {put} the bookshelf {together} in an hour.` | 예문에서 빈칸이 될 부분을 `{ }`로 감쌈. 여러 개 가능. `{a|b}`로 복수 정답 허용(예: `{gonna|going to}`) |

- `빈칸 예문`은 처음에 **자동 생성 스크립트**로 채우고, 실패한 행만 사람이 고친다.
- 자동 생성 규칙(스크립트, 1회성 + 신규 행에 재실행):
  1. `표현`에서 `+ …`, `-ing`, `(…)` 같은 문법 표기를 떼어내고 단어 목록을 만든다. 괄호 안 단어는 선택(있으면 포함).
  2. `someone`, `something`, `one's`, `oneself`, `(someone)` 은 “아무 단어 0~3개”로 취급(분리형/대명사 자리).
  3. 각 단어의 활용형 후보를 만든다: 규칙 활용(-s, -es, -ed, -d, -ing, 자음 중복 + -ed/-ing, y→ied) + **불규칙 동사표**(go/went/gone, break/broke/broken, …약 200개) + be 동사(am/is/are/was/were/been/being/'m/'re/'s).
  4. 예문에서 대소문자 무시로 가장 짧게 연속 매칭되는 구간을 찾아 `{ }`로 감싼다. 사이에 낀 목적어는 빈칸에서 제외(빈칸 여러 개로 나뉨).
  5. 매칭 실패 / 두 군데 이상 매칭 → `빈칸 예문`을 비워 두고 검수 시트(`검수필요` 필터)로 표시.
  - 샘플 300행 기준 대부분은 1~4로 해결되고, 실패는 주로 관용 표현 변형(예: `kick someone's butt` → `kick their butts`)이라 사람이 직접 고친다.
- `Drop 여부`가 채워진 행(값이 비어 있지 않음)은 **출제 제외**.
- `빈칸 예문`이 비어 있는 행도 출제 제외(앱이 잘못된 빈칸을 내지 않도록).

#### 앱에 배포하는 형식

빌드 스크립트(`tools/build-blank-data.mjs`, Node)가 시트를 읽어 `data/blank-data.json`을 만든다. 실행은 GitHub Actions 수동 실행(`workflow_dispatch`) 또는 로컬에서 `node tools/build-blank-data.mjs`.

```json
{
  "version": "2026-10-15",
  "items": [
    {
      "id": "EX-S01E01-09",
      "season": "S01", "ep": "E01",
      "expr": "put together",
      "meaning": "조립하다, 한데 모아 만들다",
      "level": "중급",
      "cloze": "We {put} the bookshelf {together} in an hour."
    }
  ]
}
```

- `items` 배열 순서 = **출제 순서**(시트 행 순서: S01E01 → S01E02 → …).
- 시트를 공개 CSV로 앱에서 직접 읽는 방식은 쓰지 않는다(로드가 느리고, 시트 수정 실수가 즉시 서비스에 반영되며, 검수 단계가 없음).
- 파일 크기: 약 3,200문항 × 약 150바이트 ≈ 500KB, gzip 시 약 120KB. 한 번에 로드해도 충분.

### 5.3 진도 모델

사용자별로 다음을 저장한다.

```
progress = {
  cursor: 40,            // items 배열에서 다음에 출제할 위치(0부터). = 학습 시작으로 소화한 문장 수
  sessions: 12           // 완료한 세션 수 (심연 출제 주기 계산용)
}
itemState[id] = {
  box: 'review' | 'abyss',   // 정답만 낸 새 문장은 상태를 만들지 않음 (= 학습 완료)
  reviewHits: 0..3,          // 복습에서 맞춘 누적 횟수
  wrongCount: 1,             // 총 오답 횟수(통계용)
  lastSeenAt: '2026-10-15T09:00:00Z',
  enteredAbyssAt: null
}
```

상태 전이:

```
           새 문장(학습 시작)
              │
     정답 ────┼──── 오답/모르겠음
      │                 │
  (상태 없음)            ▼
   완료               복습함 (reviewHits = 0)
                        │  복습에서 정답 → reviewHits +1
                        │  복습에서 오답 → reviewHits 유지(감소 없음), wrongCount +1
                        │
                reviewHits ≥ 3
                        ▼
                      심연 🕳️
                        │  가끔 출제되어 정답 → 심연 유지(lastSeenAt 갱신)
                        │  가끔 출제되어 오답 → 복습함으로 복귀, reviewHits = 0
```

- “3번 이상 맞추면”은 **누적 3회**로 정의(중간에 틀려도 0으로 돌아가지 않음). 연속 3회가 필요하면 설정값 `ABYSS_RULE = 'cumulative' | 'consecutive'`로 바꿀 수 있게 구현.
- 같은 날 같은 문장을 여러 번 맞혀도 1회만 인정할지: 1차 구현은 **하루 1회만 인정**(같은 세션에서 반복 출제하지 않으므로 대부분 자연스럽게 만족). 설정값 `HIT_ONCE_PER_DAY = true`.

### 5.4 학습 시작(새 문장)

- 출제: `items[cursor] … items[cursor + 9]` 10개를 **시트 순서대로**(섞지 않음 — 같은 화의 표현이 묶여 나오는 게 학습에 자연스러움). 제외 대상(Drop, 빈칸 예문 없음)은 건너뛰고 10개를 채움.
- 각 문항에 답할 때마다 즉시 저장하고 `cursor`를 1 증가. → 세션 중간에 나가도 푼 문항까지 반영되고, 다음 “학습 시작”은 남은 곳부터 새 10개.
- 정답 → 상태 없음(완료). 오답/모르겠음 → 복습함(`reviewHits = 0`).
- **힌트를 쓰고 맞춘 경우**: 정답으로 처리하되 복습함에 넣는다(혼자 힘으로는 못 맞춘 것이므로). 결과 화면에 “힌트” 표시.
- 모든 문장을 다 소화하면(`cursor ≥ 전체 수`): 학습 시작 버튼 대신 “🎉 전체 완료! 복습으로 마무리해 보세요” 카드. 시트에 문장이 추가되면 자동으로 다시 활성화.

### 5.5 복습

- 버튼 표시: 복습함 개수. 0개면 비활성(“틀린 문장이 없어요”).
- 세션 구성(최대 10문항):
  1. **복습함**에서 우선순위대로 최대 10개: ① `reviewHits` 낮은 순 → ② `lastSeenAt` 오래된 순 → ③ 오답 많은 순. 단, **직전 세션에 나온 문장은 가능하면 제외**(복습함이 10개 이하면 예외).
  2. **심연 끼워 넣기**: 아래 조건을 만족하면 심연에서 1~2개를 뽑아 복습 문항 자리를 대신한다.
     - 심연 문항이 있고, 그 문항이 심연에 들어간 지(또는 마지막으로 확인한 지) **7일 이상** 지났을 것.
     - 복습 세션 **2회에 1번** 꼴(`progress.sessions % 2 === 0`), 한 번에 최대 2개(복습함이 5개 미만이면 최대 3개).
     - 뽑는 순서: 마지막 확인이 오래된 것부터.
  3. 전체 순서는 섞어서 출제(복습은 무작위가 효과적).
- 복습함이 10개 미만이면 그 개수(+심연)만큼만 진행. 문항 수가 0이면 버튼 비활성.
- 풀이 화면에서 문항 태그로 구분: `🔁 복습`, `🕳️ 심연에서 올라옴`.

### 5.6 풀이 화면 (프로토타입 `#/blank/play/new`)

구성:

- 상단: 진행 막대 + `n / 10`, 그 아래 점 10개(맞음 초록 / 틀림 빨강 / 현재 테두리).
- 카드: `S01 · E01` · 난이도 칩 · (복습/심연 태그) → **뜻**(“뜻 · ~을 피하다, 가까이 가지 않다”) → 빈칸이 들어간 예문.
- 빈칸: 문장 안에 인라인 `<input>`. 빈칸이 여러 개면 여러 개.
- 하단: `💡 힌트` · `모르겠음` · `확인`.

입력:

- 첫 빈칸에 자동 포커스, 모바일에서 키보드가 바로 올라오게 함.
- 입력 속성: `autocapitalize="off" autocorrect="off" spellcheck="false" autocomplete="off"` — 자동 대문자/자동 수정이 정답을 바꾸지 않게.
- 빈칸 정답과 일치하는 순간 **다음 빈칸으로 자동 이동**(마지막 빈칸이면 이동 없음).
- `Enter` = 확인. 정답/오답이 표시된 상태에서 `Enter` = 다음 문제.
- 빈칸 하나라도 비어 있으면 확인 시 토스트 “빈칸을 모두 채워 주세요”(모르겠음은 예외).
- 빈칸 너비: 정답 글자 수 + 1 (최소 3글자). ⚠️ 글자 수가 힌트가 되는 문제가 있음 → [남은 결정 사항](#102-남은-결정-사항) D-3.

채점:

- 정규화 후 빈칸별 완전 일치: 소문자, 곡선 따옴표 → `'`, 앞뒤/중복 공백 제거. 대소문자는 구분하지 않음(문두 `Steer`를 `steer`로 써도 정답).
- 복수 정답 `{a|b}`: 하나라도 같으면 정답.
- 모든 빈칸이 맞아야 문항 정답.
- 오타 1글자(편집 거리 1)는 **오답**으로 처리하되 피드백에 “아까워요! 철자를 확인해 보세요”를 표시(스펠링 학습 목적 유지).

피드백:

- 정답: 빈칸 초록, 이모지 버스트, 0.65초 뒤 자동으로 다음 문제.
- 오답: 빈칸 빨강 취소선, 아래 빨간 상자에 정답 문장(빈칸 부분 굵게) + “표현: steer clear of”. 버튼이 `다음`으로 바뀌고 힌트/모르겠음 비활성.
- 힌트: 각 빈칸에 첫 글자 + `…`를 placeholder로 표시하고, 안내 줄에 표현 원형 표시(“힌트: 표현 원형은 "steer clear of"”). 문항당 1회.
- (선택) 오답/정답 확인 후 🔊 버튼으로 문장 듣기(단어 공부의 TTS 재사용).

### 5.7 세션 결과 (프로토타입 `#/blank/result`)

- `6 / 10 정답` + 학습 시작이면 “진도 40 / 3,183 문장”, 복습이면 “남은 복습 n개 · 심연 n개”.
- 문항 목록: ⭕/❌, 표현, 전체 예문, 이동 결과 칩 — `→ 복습함`, `복습 2/3`, `→ 🕳️ 심연`, `심연 → 복습함`, `심연 유지`.
- 버튼: `복습하기`(복습함이 있을 때) · `다음 10문장` · `빈칸 홈으로`.

### 5.8 빈칸 홈 (프로토타입 `#/blank`)

- 진도 카드: `40 / 3,183 문장`, 퍼센트, 진행 막대, “다음 학습: 41~50번째 문장 · S01 · E05부터 이어서”.
- `학습 시작`(큰 검정 버튼), `복습 n`(빨강 숫자), `🕳️ 심연 n`(보라 숫자, 탭 시 심연 목록 보기 — 읽기 전용, 2차).
- 복습 규칙 설명(새 문장 → 틀리면 → 복습함 → 3번 맞추면 → 심연).
- 복습함 미리보기: 표현 + 뜻 + 정답 횟수 점 3개.
- 비로그인: “지금은 이 기기에만 진도가 저장돼요 [로그인]” 배너.

### 5.9 저장 시점과 동기화

- 문항 하나 답할 때마다 `blank_attempts` 행 1개 insert + `blank_item_state` upsert + `blank_progress` update(학습 시작일 때). 비로그인은 같은 구조를 `localStorage`에.
- 네트워크 실패 시: 로컬 큐(`localStorage['esc.pending']`)에 쌓고 다음 요청 성공 시 순서대로 재전송. 학습 흐름은 막지 않는다.
- 두 기기에서 동시에 학습한 경우: `cursor`는 큰 값, 문항 상태는 `lastSeenAt`이 늦은 쪽 채택(마지막 쓰기 우선). 세션 시작 시 서버 상태를 다시 읽어 충돌을 줄인다.

### 5.10 2차: `문장구조` 탭

- 같은 엔진을 쓰되 빈칸은 패턴의 **고정 부분**(예: 패턴 `I'm gonna + 동사원형` → 예문 `{I'm gonna} call my mom after dinner.`).
- 빈칸 홈에 `표현 / 문장구조` 덱 전환 탭을 두고, 진도·복습·심연은 덱별로 따로 관리(`deck` 컬럼).

### 5.11 수용 기준

- [ ] `We {put} the bookshelf {together} in an hour.` 문항에 빈칸 2개가 문장 안 제자리에 표시된다.
- [ ] 첫 빈칸에 `put`을 치면 두 번째 빈칸으로 포커스가 이동한다.
- [ ] `Steer clear of` 문항에 `steer clear of`를 입력해도 정답이다.
- [ ] 학습 시작으로 10문장 중 4개를 틀리면 복습 버튼 숫자가 4 늘고, 다음 학습 시작은 11번째 문장부터다.
- [ ] 학습 시작 중 3번째 문항에서 나갔다 다시 들어오면 4번째 문장부터 새 10개가 나온다.
- [ ] 복습에서 같은 문장을 (서로 다른 날) 3번 맞추면 심연으로 이동하고 복습 숫자가 줄어든다.
- [ ] 심연에 들어간 지 7일이 지난 문장이 이후 복습 세션에 가끔 섞여 나오고, 틀리면 복습함으로 돌아간다.
- [ ] `Drop 여부`가 표시되거나 `빈칸 예문`이 비어 있는 행은 출제되지 않는다.

## 6. 기존 기능 이관 — 단어 공부

- 기능은 ESC_WORD 그대로(학습 카드, TTS, 테스트, 60% 통과). 화면만 통합 디자인으로 교체.

  - 테스트 결과에 문항별 정답/오답 점, `다시 테스트` 버튼.
  - 결과 저장(3.5).
- 이후 개선 후보(이번 범위 아님): 단어 테스트에서 틀린 단어를 빈칸 학습의 복습함과 같은 방식으로 관리.

## 7. 내 기록 화면

`#/me` (프로토타입 참고). 비로그인 시 “로그인하면 기록을 볼 수 있어요” 카드 + 로그인 버튼.

구성:

1. 프로필: 이니셜 아바타, 이름, 로그인 수단, 자동 로그인 켜짐/꺼짐.
2. 한눈에 보기(타일 4개): 영작 완료 `n / 전체`, 단어 테스트 통과 `n / 전체`, 빈칸 진도 `n 문장`, 복습/심연 개수. 각 타일에 진행 막대.
3. 최근 4주 학습 잔디(하루 학습 문항 수 기준 4단계 색). 연속 학습일 계산(홈의 “연속 학습”에도 사용).
4. 영작 숙제 목록: 완료 ✓ / 미완료 —, 완료한 숙제는 스피킹 비율(`🎤 32%`), 미완료는 날짜. 목록 화면(`#/order`)의 `전체 / 안 한 숙제 / 완료` 탭과 같은 데이터.
5. (2차) 단어 세트 목록, 빈칸 오답 많은 표현 Top 10.
6. 로그아웃, (설정) 계정 삭제.

“숙제를 했는지/안 했는지”는 목록 화면에도 반영한다: 로그인 시 각 숙제 카드 오른쪽에 `✓ 완료` 또는 `미완료` 칩, 단어 세트는 `✓ 5/6` 또는 `미응시`.

## 8. 데이터 모델 (DB 스키마)

Supabase(Postgres). 모든 테이블은 RLS로 **본인 행만** 읽기/쓰기.

```sql
-- 프로필 (auth.users와 1:1)
create table profiles (
  user_id      uuid primary key references auth.users on delete cascade,
  display_name text not null,
  provider     text not null,                -- 'kakao' | 'google'
  created_at   timestamptz not null default now()
);

-- 영작 완료 기록 (시도마다 1행)
create table order_attempts (
  id                 bigint generated always as identity primary key,
  user_id            uuid not null references auth.users on delete cascade,
  package_id         text not null,          -- data.json의 id (예: ord-20260601-dont-tell-me)
  completed_at       timestamptz not null default now(),
  duration_ms        integer not null,
  retry_count        integer not null default 0,
  tap_words          integer not null,
  voice_words        integer not null,
  client_attempt_id  uuid not null,          -- 게스트 병합/재전송 시 중복 방지
  unique (user_id, client_attempt_id)
);
create index on order_attempts (user_id, package_id);

-- 단어 테스트 기록
create table word_attempts (
  id                 bigint generated always as identity primary key,
  user_id            uuid not null references auth.users on delete cascade,
  set_id             text not null,
  mode               text not null check (mode in ('study', 'test')),
  score              integer,
  total              integer,
  passed             boolean,
  completed_at       timestamptz not null default now(),
  client_attempt_id  uuid not null,
  unique (user_id, client_attempt_id)
);

-- 빈칸: 덱별 진도
create table blank_progress (
  user_id    uuid not null references auth.users on delete cascade,
  deck       text not null default 'expr',   -- 'expr'(표현) | 'pattern'(문장구조)
  cursor     integer not null default 0,
  sessions   integer not null default 0,
  updated_at timestamptz not null default now(),
  primary key (user_id, deck)
);

-- 빈칸: 문항 상태 (복습함/심연에 있는 문항만 존재)
create table blank_item_state (
  user_id          uuid not null references auth.users on delete cascade,
  item_id          text not null,            -- 시트 ID (예: EX-S01E01-07)
  box              text not null check (box in ('review', 'abyss')),
  review_hits      smallint not null default 0,
  wrong_count      smallint not null default 1,
  last_seen_at     timestamptz not null default now(),
  last_hit_on      date,                     -- 하루 1회 인정 규칙용
  entered_abyss_at timestamptz,
  primary key (user_id, item_id)
);
create index on blank_item_state (user_id, box);

-- 빈칸: 풀이 로그 (통계·잔디용)
create table blank_attempts (
  id                bigint generated always as identity primary key,
  user_id           uuid not null references auth.users on delete cascade,
  item_id           text not null,
  kind              text not null check (kind in ('new', 'review', 'abyss')),
  correct           boolean not null,
  used_hint         boolean not null default false,
  answered_at       timestamptz not null default now(),
  client_attempt_id uuid not null,
  unique (user_id, client_attempt_id)
);

-- RLS (모든 테이블 동일 패턴)
alter table order_attempts enable row level security;
create policy "own rows" on order_attempts
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);
-- … profiles, word_attempts, blank_progress, blank_item_state, blank_attempts 동일
```

- 콘텐츠(숙제, 단어, 빈칸 문항)는 DB에 넣지 않는다. 기록은 콘텐츠 ID 문자열로만 참조.
- 게스트 `localStorage` 구조는 위 테이블을 그대로 JSON 배열로 옮긴 형태(`{orderAttempts:[], wordAttempts:[], blankProgress:{}, blankItemState:{}, blankAttempts:[]}`) → 병합 시 그대로 upsert.
- 빈칸 상태 갱신은 클라이언트 계산 후 upsert. 동시성 문제가 커지면 `answer_blank(item_id, kind, correct, used_hint)` Postgres 함수(RPC)로 옮겨 서버에서 원자적으로 처리.

## 10. 구현 순서와 남은 결정 사항

### 10.1 구현 순서

| 단계 | 내용 | 산출물 |
|---|---|---|
| 0 | UI/UX 프로토타입 | ✅ 이 저장소 (현재) |
| 1 | 통합 골격: 라우터, 공통 레이아웃, 기존 두 서비스 이관(실제 `data.json` 사용), 콘텐츠 `id` 부여 스크립트 | 로그인 없이 기존 기능 100% 동작 |
| 2 | 빈칸 데이터 파이프라인: 시트에 `ID`·`빈칸 예문` 열 추가, 자동 생성 스크립트, 검수, `blank-data.json` 빌드 | 검수 완료된 JSON |
| 3 | 빈칸 학습(게스트 `localStorage` 저장 기준): 학습 시작/복습/심연 | 비로그인으로 빈칸 기능 완성 |
| 4 | Supabase 설정 + 카카오/구글 로그인 + 자동 로그인 + 기록 저장/병합 + 내 기록 | 로그인 기능 완성 |
| 5 | 영작 음성 입력 + 탭/스피킹 비율 | 음성 기능 완성 |
| 6 | 기존 두 사이트 리다이렉트, 개인정보 처리방침, 실제 기기 QA(카카오톡 인앱 포함) | 출시 |

단계 3을 4보다 먼저 하는 이유: 빈칸 학습은 게스트 저장만으로도 완전하게 동작하므로, 로그인 없이 먼저 써 보며 복습 규칙을 다듬을 수 있다.
